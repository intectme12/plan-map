# AI 바이브 코딩 규칙

> Cursor, Codex, Claude Code 등의 코딩 AI에게 지시할 때, 매 페이지·화면마다 새로운 스타일을 만들어내지 않고 제품의 디자인 시스템을 일관되게 구현하도록 하기 위한 전용 규칙.
>
> 시각적 토큰/컴포넌트는 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), 동작/UX 체크리스트는 [UI_RULES.md](UI_RULES.md) 참고.

---

# 1. AI에게 구체적인 디자인 규칙을 전달한다

AI에게 "예쁘게 만들어줘"라고 요청하지 말고 구체적인 디자인 규칙을 전달한다.

나쁜 예:

> "예쁘게 만들어줘."

좋은 예:

> "깔끔한 SaaS 대시보드 스타일을 사용한다."
> "여백을 넉넉하게 사용하고 색상을 절제한다."
> "주요 액션은 시각적으로 가장 강조한다."
> "과도한 그라디언트, 그림자, 둥근 카드를 사용하지 않는다."

---

# 2. AI / 바이브 코딩 전용 규칙

Cursor, Codex, Claude Code 등의 코딩 AI를 사용할 때 특히 중요하다.

## 규칙 1 — 페이지보다 디자인 시스템을 먼저 정의한다

나쁜 예:

> "대시보드 만들어줘."

좋은 예:

> "기존 디자인 토큰을 사용하는 대시보드를 만든다. 8px 간격 시스템, 카드 radius, 중립적인 surface 색상, 하나의 primary accent 색상과 명확한 시각적 계층을 사용한다." (plan-map의 실제 값은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 참고)

## 규칙 2 — AI가 매번 새로운 스타일을 만들게 하지 않는다

먼저 토큰과 공통 컴포넌트를 확인한다([DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 참고). plan-map은 아직 별도 디자인 토큰 파일이 없고 Tailwind 유틸리티 클래스를 직접 쓰므로, "이미 어떤 화면에서 쓰인 클래스 조합인지"를 토큰 대신으로 취급한다.

## 규칙 3 — AI에게 기존 컴포넌트를 먼저 확인하게 한다

프롬프트 패턴:

```text
새 컴포넌트를 만들기 전에:
1. 기존 컴포넌트를 먼저 확인한다.
2. 가능하면 기존 컴포넌트를 재사용한다.
3. 적절하면 기존 컴포넌트를 확장한다.
4. 정말 필요할 때만 새 컴포넌트를 만든다.
5. 기존 디자인 토큰을 따른다.
```

## 규칙 4 — 화면별 디자인 변형을 방지한다

새로운 페이지를 추가할 때:

```text
디자인 시스템에 없는 새로운 색상, 간격, border-radius,
버튼 스타일, typography, shadow를 임의로 추가하지 않는다.
```

---

# 3. 바이브 코딩용 디자인 검수 프롬프트

AI 코딩 에이전트에게 페이지를 만들거나 검토시킬 때 사용:

```text
이 UI를 구현하기 전에 다음 디자인 규칙을 반드시 따른다.

1. 먼저 기존 디자인 시스템과 재사용 가능한 컴포넌트를 확인한다.
2. 필요한 경우가 아니라면 새로운 색상, typography, spacing, shadow, border-radius를 임의로 만들지 않는다.
3. 시각적 계층 구조를 일관되게 유지한다.
4. Semantic HTML과 접근 가능한 interaction을 사용한다.
5. 다음 상태를 모두 고려한다.
   - loading
   - empty
   - error
   - success
   - disabled
6. Desktop, Tablet, Mobile에서 반응형으로 동작하게 만든다.
7. 버튼, 입력창, 테이블, 모달, 네비게이션의 동작을 일관되게 유지한다.
8. 긴 텍스트, 데이터 없음, 대량 데이터 상황을 처리한다.
9. 과도한 gradient, shadow, animation 및 장식 요소를 사용하지 않는다.
10. 복잡한 시각 효과보다 사용성과 명확성을 우선한다.
11. 새로운 컴포넌트를 만들기 전에 기존 컴포넌트를 재사용한다.
12. 구현 후 기존 애플리케이션과 시각적 일관성을 검수한다.
```

---

# 결론

바이브 코딩에서 가장 중요한 원칙은 다음과 같다.

> **AI는 디자인 시스템을 구현해야 하며, 페이지마다 새로운 디자인 시스템을 만들어서는 안 된다.**
